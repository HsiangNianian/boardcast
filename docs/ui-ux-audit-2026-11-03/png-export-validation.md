# C47 大尺寸 PNG 与失败后的 SVG 退路

2026-11-06，基线 `99ec756`。方案要求“大图失败给 SVG 退路”，实际 PNG 编码失败时，原界面只有错误与重新导出按钮，没有说明替代格式。旧生产构建的 33 项检查中，四种失败提示检查失败，其余 29 项通过。

## 产品改动

复用现有导出错误提示，PNG **生成阶段**失败时追加中英文路径“导出 → 当前白板 → SVG 矢量图”。保留原错误和重试动作。保存权限、磁盘空间等错误继续提供原有存储恢复说明；其他格式生成失败不显示 PNG 提示。不自动更换格式或下载文件。

原有尺寸限制、输出算法与存储逻辑未改：实际下载已证实这组超宽/超高样本最长边限制为 8000 像素，SVG 可保留更大尺寸。

| 样本 | PNG 宽 × 高 | SVG 宽 × 高 |
| --- | --- | --- |
| 超宽、浅色、英文、手绘 | 8000 × 835 | 12640 × 1320 |
| 超宽、浅色、英文、自由编辑 | 8000 × 821 | 12616 × 1296 |
| 超高、深色、中文、手绘 | 1034 × 8000 | 1628 × 12600 |
| 超高、深色、中文、自由编辑 | 1028 × 8000 | 1616 × 12576 |

每份产物包含资料底图，以及位于原点负方向和底图右下外侧的自由图形。真实解码、颜色区域与边界比较确认它们可见且未截断；同一模式的 PNG 与 SVG 对应区域边界差不超过 3 像素。两种模式的尺寸差来自已有内容留白，没有把它们误判为同一输出尺寸。

## 验证范围

[PNG 检查](../../scripts/ui/check-png-export.cjs)使用真实生产 App、IndexedDB、Canvas 和下载。只在失败阶段令 PNG 编码器返回空结果，持续保留该故障时仍能从菜单导出有效 SVG；640×400 下中英文说明与动作均完整可见，原会议记录未变。

[交接检查](../../scripts/ui/check-export-handoff.cjs)另验证中英文 PNG 保存权限失败不提示换格式，回放生成失败也不受影响；原有保存、取消、焦点、重试和错误说明继续检查。这组使用受控原生 IPC，不是系统保存对话框实测。

最终构建的 PNG 33 项、交接 73 项均通过，TypeScript、播放器及主应用构建通过。入口为 `index-oVAG6Jy9.js`；174 个源文件与隔离构建副本一致，11576 个前端文件已核对并更新到 1430，旧资源和原 1423/1430 进程保持。[本地证据](evidence/implementation/png-export/)包含基线、实际下载、故障截图、报告与哈希，不随 PR 上传。产品改动仅涉及 App 与中英文文案三份源码；本批未重跑完整 Node/Rust 或进行原生安装验收。

真实内存耗尽、所有浏览器的 Canvas 限制、原生读屏和更极端的几何尺寸未验证；不据此关闭全部 C47 或 G3/G4。Windows ARM 原 Adreno 设备、Mac、实际安装升级与新用户试用仍待验收。
