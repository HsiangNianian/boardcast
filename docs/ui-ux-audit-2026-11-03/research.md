# Mac 桌面 UI/UX 调研与 boardcast 设计依据

调研日期：2026-11-03。对象：本地优先、实时会议与手绘白板应用。本文是供体验审查和重构计划使用的研究输入，不是客户端已完成改造的声明。

## 结论

推荐 **安静的会议工作台 + 有手感的白板**：借鉴 Things 的清楚层级、Linear 的稳定外壳、Raycast 的可发现操作、Audio Hijack 的可观察音频状态、CleanShot 的成果交接、Allume 的空间组织。保留 boardcast 的墨水/粉笔笔迹和逐步成图；系统按钮、录音状态、错误、保存、设置使用清晰稳定的常规控件。

判断 UI 好不好，先问用户能否清楚回答：**现在在哪场会议？正在收哪个音源？哪些话已经记录？白板还在处理什么？内容保存了吗？下一步能做什么？** 这些答案比新增颜色、玻璃效果和动效更重要。

产品边界来自 [README](../../README.md) 和 [开发优先级](../development-priorities.md)：保持本地优先；优先补全 PAD 白板与 PC 会议端到端体验；保留现有 Eval；默认仍是 SenseVoice + dynamic review + VAD；Apple SpeechAnalyzer 是 macOS 26+ 能力探测后的实验选项。调研不建议为了“统一外观”删除现有导入、导出、回放、分支、圈选或编辑能力。

## 方法与证据等级

- **D：一手说明**，本轮打开的官方手册、设计文章或产品页。可说明产品公开设计，不能证明运行质量。
- **V：图片观察**，本轮下载并实际查看的官方界面图片。Things、Linear、Allume 属此类；这些是厂商展示状态，不代表我在 Mac 上亲自操作过。
- **H：历史一手案例**，保留设计启发，但明确时间或产品生命周期。
- 未登录、购买或在真实 Mac 上逐个运行这些第三方应用；不把营销文案里的“快”“完美 UX”当测量结果。没有给这些产品打伪精确分数。
- 使用 `ui-ux-pro-max` 的可访问性、反馈、键盘、布局检查框架；本地 skill 包只有 `SKILL.md`，缺 `scripts/search.py`，设计系统命令无法运行。以下建议由实际官方资料和图片分析形成，不声称来自自动生成的评分或设计系统。

## 11 个案例

### 1. Things：界面围绕任务组织，复杂度跟着需要出现

**证据 D + V。** [产品页](https://culturedcode.com/things/)、[Quick Entry](https://culturedcode.com/things/support/articles/2249437/)、[Mac 快捷键](https://culturedcode.com/things/support/articles/2785159/)。实际查看了[官方多端界面图](https://culturedcode.com/things/2024-01-20/images/whatsnew-collage-io60.png)。

观察：Mac 左侧导航固定，主区用标题、间距、章节和少量色彩建立层级；项目正文没有被大量装饰卡片分割。Quick Entry 将捕获入口放到当前工作之外，熟悉的键盘动作可沿用。

**迁移：** 会议库、当前会议、设置位置稳定；当前任务有一个明确主操作。新手首先看到“开始会议 / 导入材料 / 体验示例”，高级参数随需求展开。会议名称、保存状态、录音状态不能被缩在相同权重的一排图标里。

**不要照搬：** 清单软件的“完成勾选”不是会议录制状态；大量依赖悬停的小按钮也不能直接用到 PAD。

### 2. Raycast：把专家效率做成可学习的路径

**证据 D。** [Action Panel](https://manual.raycast.com/action-panel)、[键盘操作](https://manual.raycast.com/keyboard-shortcuts)、[Local Models](https://manual.raycast.com/ai/local-models)。

观察：选中对象后有主操作，更多动作按上下文组织并显示快捷键，Escape 逐层返回。其本地模型说明明确：没有对应基准数据时，不显示速度与智能评分。

**迁移：** 菜单同时提供文字与快捷键；选中会议时出现继续、回放、导出等动作；选中白板内容时出现局部操作。先让现有菜单支持键盘，再评估是否需要命令面板。模型面板说明“用途、是否已安装、是否在运行、所需空间、支持能力”，不要给未测模型虚构快慢排名。

**不要照搬：** 命令面板不能成为开始录音、停止或修复权限的唯一入口；新手不应先记快捷键。

### 3. Linear：外壳、位置和动作应该可预测

**证据 D + V。** [2024 完整改版过程](https://linear.app/now/how-we-redesigned-the-linear-ui)、[2026 界面整理](https://linear.app/now/behind-the-latest-design-refresh)。实际查看了 [2024 官方界面图](https://webassets.linear.app/images/ornj730p/production/900ab5bbf41d4245dcd32122b80ed523c5a00e2f-2352x1344.png)，不将其标为 2026 截图。

观察：列表、详情、导航之间的空间关系清楚；2026 文章进一步处理顶部动作不一致、导航抢注意力、分隔线过多的问题。亮度和视觉权重服务当前内容，而非所有区域同等醒目。

**迁移：** 会议库与会议工作区共用可预测框架；通用操作固定在通用位置，视图操作留在视图附近。PAD/PC 切换是当前会议的呈现选择，不应看起来像切到了两个独立产品。

**不要照搬：** Linear 的高密度小字适合熟练桌面用户，不能变成低对比、小点击区的理由；同一视觉 token 应覆盖亮色、暗色和触摸密度。

### 4. Arc：空间性格与上下文切换（历史案例）

**证据 D + H。** [Command Bar](https://start.arc.net/command-bar-actions)、[空间颜色与创意工具](https://start.arc.net/paint-the-internet)、[官方停用公告](https://arc.net/)。官网当前公告 2026-12-22 停用，故这里只研究设计，不推荐把它当长期依赖。

观察：侧栏、Spaces、固定项目、隐藏侧栏与命令栏形成上下文组织；空间颜色使不同工作环境可辨识。

**迁移：** 同一会议的材料、白板页、转写和回放可以形成清楚的工作上下文；有限品牌色帮助辨识当前会议或模式。专注视图应能一键恢复到原位置。

**不要照搬：** 隐藏所有导航、把功能埋在手势里、为每场会议新增一套主题设置。视觉自由不能让用户猜现在在哪个上下文。

### 5. Craft：内容本身就是交付物

**证据 H。** [官方 Focus Mode 发布说明](https://www.craft.do/s/fegziZPWTrBfn0)的搜索索引可读；直接页需要 JavaScript，当前主站抓取超时，未验证最新版交互。该案例仅引用公开历史机制：Mac/iPad 可隐藏侧栏和页头，并用 Escape 或快捷键退出。

**迁移推论：** 总结/纪要的阅读排版要接近可交付文档；“专注”应是可撤销的视图变化，保留录音/保存等关键状态。导出前让用户看清实际内容与格式用途。

**不要照搬：** 不为纪要额外引入块编辑器、卡片主题系统或新的文档格式；现有 Markdown 与总结能力应先形成顺畅闭环。

### 6. Bear：个性落在阅读体验，而非每个控件

**证据 D。** [Typography](https://bear.app/faq/typography-options/)、[主题说明](https://bear.app/faq/about-free-and-pro-themes-in-bear/)、[帮助目录](https://bear.app/faq/)。

观察：字体、行宽、行距可分别调整；主题包括高对比方向；信息结构允许侧栏、列表和正文有不同职责。这里依据官方功能说明，未实测其无障碍合规性。

**迁移：** 转写、总结和设置保持易读正文；手写字保留给画布。中文、日文和英文分别检查字重、混排与截断。亮暗模式不仅反转颜色，也要保持文本、选区、圈选、连线和错误的辨识度。

**不要照搬：** 不建立几十套主题；优先把白板/粉笔两种既有主题做好，并提供系统偏好与减弱动态支持。

### 7. Screen Studio：复杂任务从捕获到成果有明确阶段

**证据 D。** [产品页](https://screen.studio/)、[指南](https://screen.studio/guide/home)、[系统音频指南](https://screen.studio/guide/recording-system-audio)。采用 `screen.studio` 官方来源，排除搜索中的同名 `screenstudio.dev`。

观察：官方流程把录制、录制中控制、编辑、外观、导出分成阶段；自动缩放、画面和声音处理是面向成果的默认能力。

**迁移推论：** boardcast 应有准备、采集中、收尾、复盘的不同主操作。正在录制时优先停止与音源；结束后优先复核总结、回放和导出。自动生成白板也需要可检查与可纠正的结果，而非只能看动画。

**不要照搬：** 专业视频编辑时间线与镜头控制超出会议白板范围；不根据营销页推断真实性能或稳定性。

### 8. CleanShot X：任务做完，立即把成果交给用户

**证据 D。** [完整功能页](https://cleanshot.com/features)，重点 Quick Access Overlay、录制时间和 Capture history。

观察：截图/录屏完成后，靠近结果的小面板提供保存、复制、标注、拖到其他应用；记录阶段可显示菜单栏时间。成果的去向是流程的一部分。

**迁移：** 导出成功显示真实文件名、位置及“打开 / 在文件管理器中显示”；复制后有确认；失败能重试且保留上下文。会议结束后出现简短成果区，不强迫用户重新找导出按钮。

**不要照搬：** 不自动上传会议内容，不默认弹出第二个浮窗打断会议；本地导出和远端分享必须区别说明。

### 9. Audio Hijack：音频不是一个抽象红点

**证据 D。** [Session Basics](https://www.rogueamoeba.com/support/manuals/audiohijack/?page=sessionbasics)、[音频链路](https://www.rogueamoeba.com/support/manuals/audiohijack/?page=masteringsessions)、[Recorder](https://www.rogueamoeba.com/support/manuals/audiohijack/?page=recorderblock)、[Permissions](https://www.rogueamoeba.com/support/manuals/audiohijack/?page=Permissions)。

观察：会话可复用；输入、处理、输出以链路呈现，信号流可见；音频表可确认信号；录制与会话本身有明确区别；权限页区分系统音频和麦克风。

**迁移：** 用紧凑控件回答“麦克风 / 系统音频是否收到信号、转写是否进行、白板是否落后”。权限失败要指出哪个音源、如何恢复。区分“正在采集”“正在转写”“正在生成白板”“正在保存”；缓冲中的音频不等于已保存的录音文件。

**不要照搬：** 不建可编程音频节点编辑器，也不一次性要求所有权限。按用户选择的音源请求所需权限；本项目没有音频持久化时，不许文案暗示可回听原音频。

### 10. Freeform：自由画布也需要确定的位置

**证据 D。** [Mac 入门](https://support.apple.com/guide/freeform/frfm85d6f7b58/mac)、[官方使用指南](https://support.apple.com/en-euro/guide/freeform/welcome/mac)。指南列出场景导航、画布搜索、项目描述、位置/锁定、分享与导出等独立操作。

**迁移：** 白板有页/材料导航，选中对象或引用后能定位；长会议可按现有页与主题组织返回路径。导入 PDF 时应持续知道“哪份材料、第几页、总共几页”。为可视对象提供结构化文本访问路径。

**不要照搬：** 不为了接近 Freeform 扩张无限画布、实时多人协作、额外绘图工具。应先让现有 MAX_PAGES、页面和模式限制明确可见。

### 11. Allume（原 Muse）：让材料和思考共享空间

**证据 D + V。** [当前官网](https://allume.com/)。实际查看了 [Mac 亮色画布图](https://media.allume.com/website/2026/v4.0/screenshots/Mac%20-%20Darwin%20-%20light.webp)，并定位了[暗色对照图](https://media.allume.com/website/2026/v4.0/screenshots/Mac%20-%20Darwin%20-%20dark.webp)；暗色图仅链接，未作为已目视检查证据。

观察：截图中论文、摘录、图片、标记共处一张灰白画布，顶部有路径，工具集中在底部。官网用嵌套白板和收件区组织材料，并明确限制复杂格式与部分画布操作。

**迁移：** boardcast 的材料讨论和手绘特色值得保留；原文、摘录、批注应能追溯。页面关系与当前路径应清楚。让临时想法先进入会议，再逐步整理，不要求每句话输入前先选复杂结构。

**不要照搬：** 不引入新的任意层级嵌套模型或云协作系统；避免画布没有文字层级和可访问替代，最终成为只适合看演示的空间。

## 可迁移原则 → 审查问题

以下是研究推导出的审查标准，不代表已确认 boardcast 存在相应缺陷。

| 环节 | 应该让用户理解 | 必测情况 | 参考 |
| --- | --- | --- | --- |
| 初次启动 | 能先体验什么，开始真实会议还缺什么 | 无模型、无权限、离线、首次/非首次 | Things、Audio Hijack |
| 空态 | 一个可执行的下一步 | 全新、搜索无结果、内容清空、无总结 | Things、Raycast |
| 会议库 | 当前与历史会议的位置、保存结果 | 重命名、删除/取消、搜索、继续旧会议 | Things、Linear |
| 采集 | 已选音源、是否有信号、何时停止 | 拒绝权限、设备消失、静音、系统声+麦克风 | Audio Hijack、Screen Studio |
| 生成 | 已接收的内容与等待中的工作 | 无模型、慢请求、网络断开、失败、重试 | Raycast、Screen Studio |
| 白板 | 当前页、选中内容、变更是否可撤销 | 两种模式、圈选、撤销、长内容、导入背景 | Allume、Freeform |
| 总结 | 结论来自哪里、是否仍在生成 | 空总结、错误、跳转原话、内容更改后重算 | Craft、Bear |
| 回放 | 当前位置、播放状态、分支后果 | seek、速率、末尾、分支、离线 HTML | Screen Studio |
| 导出 | 导出什么、存到哪里、是否成功 | 每种格式、取消保存、写入失败、大文件 | CleanShot |
| 模型 | 用于转写/白板/视觉的哪个阶段 | 未安装、下载中、失败、已安装、加载中、运行中 | Raycast |
| 平台限制 | 此机器/此模式能做什么 | Web vs 桌面、旧 macOS、Apple 不可用 | Apple HIG |
| 输入与焦点 | 当前键盘操作作用于哪里 | Tab、Shift-Tab、Escape、输入法合成、快捷键冲突 | Raycast、Things |
| 可访问性 | 不靠颜色/动画/鼠标也能使用 | 深浅色、缩放、减弱动态、屏幕阅读器、触摸 | Apple HIG、WCAG |

## 三种设计方向与选择

| 方向 | 视觉与交互 | 收益 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- | --- |
| A 安静会议工作台 | 中性色外壳、固定导航、明确录音区、可收起的转写/总结、画布保留墨水与粉笔 | 大多数时间可专注讨论，出问题时仍可判断状态 | 需要梳理全局与局部动作、统一状态文案 | **推荐作为主体** |
| B 桌面纸本工作室 | 暖白纸面、手写批注、材料缩略图、节制的红色标记 | 保留鲜明身份，适合论文和教学 | 纹理/手写若进入正文和控件，会降低可读性与对比度 | 作为 A 的画布表达 |
| C 紧凑录音控制台 | 音源与信号更显眼、转写居中、生成队列与录音状态常驻 | 长会议与线上会议更安心 | 容易像监控面板，画布被边缘化 | 作为会议过程的状态层，不另建产品 |

组合方式：A 提供结构；B 只用于内容；C 提供必要状态。一次完成一个用户旅程，再扩展到其他页面。保持同一组组件和术语，避免“每个面板各画一套设计”。

## 具体设计约束，供 plan agent 采用或用实测修正

1. **主操作随阶段改变，但位置稳定。** 新建→开始；采集中→停止；收尾中→等待/查看已完成内容；结束→复盘/导出。不要把“录音开关”“会议结束”“清空白板”混为一个动作。
2. **以任务命名。** “语音转写”“白板生成”“图片理解”比引擎术语更适合一级设置；模型文件名、量化、端点等放到详情。保留必要的真实技术信息，不用不实的“推荐最快”代替能力说明。
3. **单一语义来源。** 下载完成、加载完成、就绪、正在采集、处理中和已保存各有独立文案与可验证条件；按钮禁用要就近解释原因。无信号不能伪装成“识别成功”。
4. **保留用户意图。** 错误时保留输入、文件选择、圈选关联和已完成的转写；取消与失败不同；重试不得默默创建重复会议或重复内容。
5. **把恢复写进设计。** 每种错误有下一步；权限拒绝有系统设置路径，设备变化可重选，下载中断能重试，写入失败可换位置；详细诊断按需展开。
6. **转写是重要的可访问内容。** 为画布的节点、顺序、选中、引用提供文本路径；实时状态用克制的通知，不能让读屏逐笔播报动画。
7. **桌面与 PAD 共用信息结构，采用不同交互密度。** 键盘菜单与鼠标右键在桌面提供效率；PAD 不依赖 hover。触摸主要动作建议至少 44×44 CSS px。WCAG 2.2 AA 的 24×24 目标要求有例外，不能把建议值误称为该标准的统一硬性数值。
8. **视觉验收可测。** 常规正文对比度至少 4.5:1，大字与关键非文本控件按 3:1 检查；保持可见焦点，不能用颜色作为状态的唯一提示；缩放时主要动作不消失，遵循减少动态偏好。
9. **macOS 习惯融入现有技术栈。** 评估应用菜单、设置入口、标准编辑快捷键、窗口恢复和原生文件选择；不把“Mac 味”理解成更换框架或模仿交通灯。完整键盘路径与焦点恢复比装饰性的原生感更重要。
10. **记录验证边界。** 模拟 IPC/浏览器中的 Apple 可用态仅用于界面测试；真正的安装、权限、设备切换、长时间采集必须在受支持 Mac 上验收。产品设计可先完整制定，结果不得伪报为硬件实测。

标准依据：[Apple Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/)。上述约束是 boardcast 设计建议，不是第三方应用已符合这些标准的证明。
