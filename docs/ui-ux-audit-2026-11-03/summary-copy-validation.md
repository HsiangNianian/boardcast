# C57 摘要复制的会议隔离与键盘返回

2026-11-06，基线 `d30155d`。生产界面配合受控剪贴板回复的 15 项基线检查中，9 项失败：切会后保留旧复制文本/编辑状态、迟到回复在新会触发回退与通知、旧请求覆盖新格式，以及复制与关闭回退框后的焦点丢失。

## 改动

- 摘要组件以会议 ID 为 key，切到另一场会议时重建编辑和手动复制界面状态；已保存的摘要仍由原存储流程读取。
- 每次复制标记请求顺序，并检查触发按钮仍属于当前界面。较早请求或已离开会议的回复，不再执行旧剪贴板回退、显示手动文本或更新通知。
- 旧式剪贴板回退结束后恢复原焦点；手动复制框只在用户仍停留于触发按钮时自动选中文本。关闭时返回对应复制按钮；摘要已删除时返回仍可操作的摘要区域。
- 长摘要在窄窗口关闭手动复制框时，允许浏览器把返回按钮滚到可见位置；只恢复焦点而禁止滚动的中间实现曾使按钮留在屏幕外，已由实际键盘检查复现并修正。

产品改动集中在 `src/ui/Summary.tsx` 和 App 的组件 key；中英文说明改为“请选中文本”，避免用户转去输入后仍声称文本已经选中。不新增依赖或存储字段。已经提交给操作系统的剪贴板写入无法撤回，此处隔离的是后续回退、界面状态与通知。

## 运行证据

[新增脚本](../../scripts/ui/check-summary-copy.cjs)使用真实生产 App、两份 IndexedDB 会议和实际会议库切换，控制 Clipboard API / 旧式复制的成功、失败和迟到顺序。基线的 9 项问题修复后，另补同会焦点、说明和删除边界检查：

- Markdown 与纯文本准确；失败文本完整选中，正常复制与关闭手动框的焦点正确。
- 两份非空摘要之间切换，不遗留上一场的复制内容和编辑状态；迟到成功/失败均不改变新会输入或通知。
- 两次复制乱序完成时，只接受最新格式；同会中用户已转去输入时，迟到失败保留输入焦点。
- 纯复制/切会操作保持两份原记录字节不变；显式删除后的关闭焦点和撤销恢复通过，另一场会议仍保持不变。

最终复制 **22 项**、原有摘要 **21 项**、复盘 **4 组**检查通过，包括 80 行中日英文本在 640×400 下的 Tab→Enter 返回与可见命中。TypeScript、播放器和主应用构建通过，没有重跑完整 Node/Rust。入口为 `index-Cb1jvS84.js`，本地 [证据目录](evidence/implementation/summary-copy/)保留基线、截图和报告，未随 PR 上传。
