# 圈选指代回归

`boardcast-tools agent-eval . board.json --set pointing --label qwen3.5-4b-q4-k-m --repeat 3`

18 段合成开发用例，中英文各 9 段：圈一个划掉、圈两个划掉、明确保留、星标、明确名称覆盖圈选、在圈选话题下补要点、连续两句切换圈选，并用完全相同的话换圈另一个条目/话题做对照。初始板书固定，圈选 ID 因此不依赖模型上一轮的编号。每遍深拷贝初始板书，避免前一遍的修改污染下一遍。

这组的要点 F1 测已有条目的保留/归属与新增条目，不代表从空板提取要点的质量。原有开发集和留出集应另外运行并报告。圈选集不用于修改提示词后的留出验证；也不测试鼠标/触屏、ASR 或请求排队。

划掉 F1 与原有“标记命中”分开：对 `gold.struck` 中的目标与最终板书上整节点的“划掉”做一对一名称/别名匹配，误划和重复预测计入假阳性，漏划计入假阴性。`struck: []` 明确表示不应划掉任何节点；没有划掉标注的旧用例不计该指标。预测与目标都为空时 F1 为 1，仅一方为空时为 0。报告沿用逐段宏平均，不是所有节点汇总的微平均；无划掉目标的保留样本也在宏平均中。原文片段上的 `spans` 标记不在这个指标范围内。

请求错误会在报告中计数并使评测退出码非零；有错误的分数不能作为模型质量结果。逐句输出和最终板书保存在 `eval/reports/`。

## 2026-11-01 实测

代码基于 PR #59 的 `88735c2`，本次只增加评测、评分和 CI，不改模型提示词。模型为仓库默认 `Qwen3.5-4B-Q4_K_M.gguf`，SHA256 `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`。llama.cpp **b11954 / f1a7dea99** Vulkan，RTX 4060 Laptop 8GB，4096 上下文、单 slot、2 个 CPU 线程；请求 temperature=0、关闭思考、沿用应用的 GBNF 和 160 输出 token 上限。

| 集合 | 段数 × 遍数 | 要点 F1 | 划掉 F1 | 标记命中 | 延迟 p50 / p95 |
|---|---:|---:|---:|---:|---:|
| 原开发集 | 27 × 1 | 0.678（11 段） | 1.000（3 段） | 0.850（10 段） | 390 / 873 ms |
| 原留出集 | 27 × 1 | 0.899（11 段） | 1.000（3 段） | 0.796（9 段） | 421 / 811 ms |
| 圈选集 | 18 × 3 | 1.000 ± 0.000 | 1.000 ± 0.000 | 1.000 ± 0.000 | 299 / 738 ms |

三组请求错误均为 0。圈选集三个指标均覆盖 18 段，三遍分数相同；延迟为本机逐句请求测量，不是音频端到端延迟。旧两集的划掉正例数量少，不足以支持一般场景“不会误划”的结论。

对照输出（中英文均通过）：同一句“把这个划掉，暂时不做。”，圈 `n2` 时返回 `M n2 划掉`，圈 `n4` 时返回 `M n4 划掉`。同一句“在这个话题下面补一条：回滚演练。”，圈 `n1` 时返回 `L n1 「回滚演练」`，圈 `n5` 时返回 `L n5 「回滚演练」`。明确名称覆盖圈选的样本，以及下一句切换圈选的样本也通过。

保留的失败：开发集 `bs-pipeline` 把画像挂到了“情感打分”下，遗漏 graphRAG 话题，并把星标打到了话题而不是“监控任务”条目；`assign-shared` 没有正确表达共同负责人，要点 F1 为 0。留出集有一次不该出现的“售后服务 → 支付网关”连线，并漏掉了“回滚脚本没人维护”的强调。未据此调整提示词或留出标注。
