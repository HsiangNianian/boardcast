# Browser regression checks

Use an existing Playwright installation and Chromium; no project dependency is added.
Start the development server separately, then run:

```sh
PLAYWRIGHT_PATH=/path/to/node_modules/playwright node scripts/ui/run-checks.cjs http://127.0.0.1:1423
```

Optional `CHROMIUM_PATH` selects a system browser. If unset, the runner uses `/usr/bin/chromium` when present, otherwise Playwright's browser. To run individual checks, append their filenames, for example `check-dialogs.cjs check-maintenance.cjs`. Each check gets a fresh browser context and a unique temporary evidence directory, printed by the runner, as `(page, baseUrl, evidence)`; checks that need only the first two arguments may ignore it.

- `check-page-generation.cjs` runs the production App with real IndexedDB and held synthetic model replies. It checks navigation during generation, per-page queues/results, retry while editing, undo/redo, content and keyboard navigation, a typed page command, new-page generation, cold reload, and late replies after switching meetings. `check-transcript-state.cjs` also checks that a legacy line without a page is retried on the first board. Native real-model evidence is in [page-generation validation](../../docs/ui-ux-audit-2026-11-03/page-generation-validation.md).
- `check-page-sources.cjs` imports a real three-page PDF whose reference page is skipped, checks source pages 1 and 3 in thumbnails, location and both page selectors, then opens an actual HTML export offline. Its 18 checks include cold reload, a blank page without an inherited source, live Chinese labels, keyboard navigation and the 34px compact selector calibrated against native WebKit clipping. Rebuild both player and main app first; native import/cold restore and the separate 16-case real-zoom matrix are in [page-source validation](../../docs/ui-ux-audit-2026-11-03/page-sources-validation.md).

- `check-dialogs.cjs` mounts the actual SettingsPanel and shared Dialog: six categories, initial focus, both Tab boundaries, background inertness, `/` isolation, nested Escape, busy dismissal, remote consent/drafts, narrow layout, retained category scroll, and return focus after parent/child close.
- `check-maintenance.cjs` also checks shared update-check timeout/network messages in both languages, preserving unknown details and a no-update result. It mounts actual UpdatePanel/DiagnosticsPanel and uses a controlled native IPC bridge: download/signature/save/install failures, retry without another verified download, save before each install, canceled diagnostic save, and failed/successful retries. Held downloads allow Later/Escape and retain progress across reopening; completion waits for an explicit Save and restart before invoking the save hook. Diagnostic checks cover multilingual log/error/Apple-error samples, Windows paths, credentials, exact preview-to-ZIP bytes and 640×400 English/Chinese reachability. It never downloads or installs an update.
- `check-native-diagnostics.py <evidence-directory>` verifies captured Linux Tauri screenshots/AX state and the actual before/after ZIP files, including CRC, sensitive samples, cancellation, EACCES, preserved target bytes and successful retry. Build identity, native steps and boundaries are in [native-diagnostics-validation.md](../../docs/ui-ux-audit-2026-11-03/native-diagnostics-validation.md).

- `check-theme-contrast.cjs` measures 30 rendered color pairs across both themes: 18 selected CSS token pairs and all six speaker colors in each theme. It waits for the App and styles, with transitions disabled only on the measurement probe. It is a targeted contrast check, not a complete WCAG audit.
- `run-touch-targets.cjs <preview-url> <evidence-directory>` is a separate runner using the visual-matrix native fixture and an existing Playwright installation. It measures 44×44px targets, viewport bounds and center hit testing across 16 language/theme/viewport combinations, including 480×720 portrait. It touches navigation, menus and dialogs; no audio or user files are used. Set `PLAYWRIGHT_PATH` / `CHROMIUM_PATH` as for the other runners; optional `TOUCH_CASE` filters case names. This is browser emulation, not physical touch-device acceptance. See [touch and contrast validation](../../docs/ui-ux-audit-2026-11-03/touch-contrast-validation.md).
- `run-compact-header.cjs <preview-url> <evidence-directory>` checks saved/pending/failed/retried feedback after toolbar focus, More/Import/Export keyboard navigation, dialog return focus, empty browser file selection, and breakpoint changes in 24 language/theme/window/pointer combinations. It uses controlled native storage and no user files. Set `PLAYWRIGHT_PATH` / `CHROMIUM_PATH`; `HEADER_CASE` optionally filters case names. `meeting-action.cjs` resolves shared header actions through More at compact widths and waits for the responsive rendering before returning a locator. The visual and touch runners also exercise the compact menu; browser file-selection cancellation does not establish native OS dialog behavior. See [compact-header validation](../../docs/ui-ux-audit-2026-11-03/compact-header-validation.md).

Run component fixtures on the development origin. Run production app checks separately after building, for example `node scripts/ui/run-checks.cjs http://127.0.0.1:1430 check-workbench.cjs check-scene-roundtrip.cjs check-lifecycle.cjs`. The runner writes a screenshot to `/tmp/boardcast-check-…-failure.png` when a check fails.

The remote-privacy check uses named hosts to exercise consent and a misleading `127` prefix while keeping all traffic on the test machine. `CHROMIUM_HOST_RULES` applies only to this test browser and also disables its proxy; it does not edit system DNS or proxy settings. CHROMIUM_HOST_RULES='MAP boardcast-a.test 127.0.0.1, MAP boardcast-b.test 127.0.0.1, MAP 127.boardcast.test 127.0.0.1' \

- `check-preparation.cjs` mounts actual Preparation with protocol-shaped native capability fixtures: explicit start only, missing transcription/input, Apple OS/assets/Auto prerequisites, capability refresh, transcript-only start, startup failure/cancel, and browser typing. It does not sample audio or download resources.

- `bash scripts/ui/check-virtual-input.sh` creates an isolated PulseAudio/PipeWire null sink, sends synthetic audio only to that sink, runs the opt-in CPAL test, and cleans up the sink/WAV. It never selects a default or physical microphone.

Fixtures under `fixtures/` are only served by Vite for these checks; they are not build entries. These checks do not establish native macOS keyboard/VoiceOver behavior, real microphone finalization, or actual signed update installation/restart. The Settings fixture uses web availability; desktop model/audio capabilities are exercised elsewhere.

`run-visual-matrix.cjs` is a separate runner for the 24 language/theme/window/zoom combinations. It creates temporary Chromium profiles and a temporary extension that calls `chrome.tabs.setZoom`, records the actual CSS viewport, DPR and visual viewport scale, and removes those profiles on completion. It uses a controlled native bridge for a populated, listening-state layout without recording audio. Run it against an isolated production preview:

```sh
PLAYWRIGHT_PATH=/path/to/node_modules/playwright node scripts/ui/run-visual-matrix.cjs http://127.0.0.1:1424
```

The checks exercise reachable stop/close controls, content and settings navigation, menu keys and dialog focus; browser zoom is not simulated by changing CSS or device scale factor.
